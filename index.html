提取到的是“频域上的形状”，并自动带出 180° 镜像。这正是 ARG 里可以当线索用的现象。

这个工具在做什么

把一张照片 A 做二维傅里叶变换，在频谱上用鼠标画出图案 B，工具会把 B 选中的频点做极微小的扰动，再逆变换回空间域得到 Ab。 玩家拿到 A 与 Ab 两份原文件后，各自做傅里叶变换、相减、取阈值，就能在频谱差分里重新看见 B 的形状。

三条硬性约束（工具已自动处理）

  • 共轭对称：实图像的频谱满足 F(−u,−v) = conj(F(u,v))。所以画板不限制你在哪半边画，但每一个被选中的频点，工具都会自动把它的对径点一起改，逆变换才不会出现虚部伪影。
  • DC 与低频：中心点是直流分量，必须保持实数；中心列被禁用，低频环带默认避开，避免整张图变亮变暗或出现低频条纹。
  • 无损保存：微小扰动低于 8 位量化步长，用 8 位 PNG / JPEG / 截图都会把它抹掉。分发请用 16 位 PNG 或 float32 TIFF。

色彩处理：一幅频谱，还是四幅？

  • 保留彩色：先把 RGB 平均成一幅灰度频谱，同一个扰动等量加到三个通道，任何通道都能解出同一份图案。
  • 灰度输出：同上，只是输出只有灰度。
  • 四通道独立：把图拆成 R / G / B / A 四张单通道图，每张各有自己的傅里叶画板、自己的选点、自己的扰动。 R 板上的图案只会出现在 R 通道的频谱里，G 板只出现在 G 通道……所以一张图能同时藏 四份互不相同 的信息， 解出来是四张独立图案。画板上方的 R / G / B / A 按钮就是切换这四块板子。

代价与注意：导出必须是 4 通道文件（16 位 RGBA PNG 或 float32 RGBA TIFF）；解谜时也不能先把 alpha 合成进颜色， 否则 A 通道的改动会轻微牵连 R/G/B。照片类素材的 A 通道通常整片不透明，它的频谱几乎只有直流分量， 所以 A 画板底色发黑是正常的，照样能画、照样能解。

参数怎么调

  • 扰动强度 δ：单位是满量程（1.0 = 255 级）。8 位量化在频域的等效噪声约 σ = N·(1/255)/√12，512 尺寸下约 0.58。δ 取 3～6 即“肉眼完全看不见但 8 位也能扛”，取 0.5 以下就只有高精度格式能救回来。
  • 频带内径：越大越隐蔽，但图案边缘越容易糊。0.10～0.20 是常用区间。
  • 选点密度 / 上限：点越少越隐蔽，越稀疏。差异图里的笔画会变“沙砾感”，这本身也是 ARG 的味道。
  • 密钥：控制稀疏采样与符号，决定最终选了哪些点。同一密钥必须同时出现在出题与解题流程里才能复现。

出题流程建议

  1. 选一张构图干净、细节丰富的照片，尺寸拉到 512。
  2. 在画板上写一个词或画一个符号（任意位置都行，越靠近中心越容易被低频吃掉）。
  3. 看“质量指标”：PSNR 应高于 55 dB，最大像素差个位数，8 位检测余量 ≥ 3。
  4. 导出 16 位 PNG（或 float32 TIFF）与谜题包 JSON，自己再走一遍“解码”标签页确认能读出来。
  5. 把原图与修改图一起发给玩家，并明确提示：不要截图、不要转格式、不要压图。

镜像现象

差分图里会同时出现 B 和它旋转 180° 的镜像。这不是 bug：共轭对称决定了差分必然中心对称。 可以直接当线索用（“频谱里出现一正一反两个字”），也可以只让玩家看右半边。

为什么不能当通信式隐写

这套方案没有抗压缩能力。任何重采样、JPEG、平台二次压缩都会把小于量化步长的扰动洗掉。 它适合做“必须使用原始文件”的谜题层，不适合做需要过社交平台的信息传递。
